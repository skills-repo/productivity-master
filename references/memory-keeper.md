# 记忆管家 · 深层 Playbook

> 配套 `skills/memory-keeper/SKILL.md`。本文写「子技能装不下的」决策方法论：
> 何时该写记忆、三层记忆文件怎么分、Zettelkasten 怎么连、间隔回顾怎么排、以及踩坑清单。
> 不是 SKILL.md 的复制，是它背后的判断与操作细节。

## 1. 决策树：这条信息该不该记、记到哪

```
收到一条信息（偏好 / 决策 / 知识点 / 上下文）
│
├─ 只和当前这次任务有关、做完即弃？ → 不记，留在会话内
│
├─ 跨会话仍要用（"以后默认…" / "上次怎么定的"）？
│   ├─ 项目级约定（命令/架构/边界） → 写进项目 CLAUDE.md / 项目记忆文件
│   ├─ 用户长期偏好/身份 → 写进 MEMORY.md（用户级长期记忆）
│   └─ Agent 自身身份契约 → 写进 AGENTS.md（仅 agent 仓库）
│
├─ 是 reusable 知识点（概念/方法/链接）？
│   ├─ 单条原子、可独立成立 → 写一条 Zettelkasten 笔记
│   └─ 需依附某主题 → 进该主题的 notes 区
│
└─ 是待办/动作？ → 进任务系统（不在记忆文件里堆 action）
```

**铁律**：记忆文件只存「结论 + 为什么」，不存待办清单；待办归任务系统。

## 2. 三层记忆文件分工

| 文件 | 层级 | 存什么 | 不存什么 |
|------|------|--------|----------|
| `CLAUDE.md` / 项目记忆 | 项目契约 | 项目约定、常用命令、架构边界、禁区 | 用户隐私、闲聊 |
| `MEMORY.md`（用户级） | 长期记忆 | 用户偏好、跨项目决策、反复踩的坑 | 一次性任务细节 |
| `AGENTS.md` | 身份契约 | Agent 角色/边界/工作流 | 具体技术实现 |

**增量追加，绝不整文件覆写**：每次只 `Edit` 追加新段，旧内容保留可追溯。整文件重写会丢历史（D32 实证过的坑）。

## 3. Zettelkasten 原子笔记法

- **原子性**：一条笔记只讲一件事，能脱离上下文独立成立。
- **链接优先于分类**：用「它和谁相关」组织（`[[链接]]` 或显式引用），而非塞进文件夹。
- **常青笔记**：写给自己未来的自己，用完整句子，避免只有当下能懂的缩写。
- **inbox → 处理 → 连接**：先无脑收，再定期把每条连到已有网络。

## 4. 信息捕获与间隔回顾节奏

| 频率 | 动作 | 目的 |
|------|------|------|
| 每次会话结束前 | 把值得留的结论追加进对应记忆文件 | 防「下次从零讲」 |
| 每日 | 清空捕获 inbox，分流到笔记/任务/记忆 | 防堆积 |
| 每周 | 回看链接缺口，补连接、删重复 | 网络生长 |
| 每月 | 间隔复习高价值笔记（spaced recall） | 对抗遗忘曲线 |

## 6. 踩坑清单

- **整文件覆写**：`echo > MEMORY.md` 会抹掉历史决策——永远用追加/Edit。
- **把待办塞进记忆文件**：记忆文件变脏、难检索；待办归任务系统。
- **记了不回顾**：收藏即遗忘；没有间隔回顾，知识库是死库。
- **分类强迫症**：先连后分；过早建文件夹导致笔记孤立。
- **记敏感信息落盘**：隐私/密钥不写记忆文件，由人决定是否留存。
- **与 prompt-optimizer 混淆**：本技能管长期知识资产，它管单次 Prompt 上下文效率——别重复造。
- **笔记不原子**：一条塞五件事，未来检索不到、复用不了。

## 7. 检查清单（落地前过一遍）

- [ ] 这条信息跨会话有用吗？（否 → 不记）
- [ ] 落点选对了吗？（项目约定 / 用户偏好 / 身份契约 / 知识笔记）
- [ ] 是追加而非覆盖吗？
- [ ] 知识点是否原子、可独立成立、有链接？
- [ ] 待办是否分流到了任务系统？
- [ ] 是否安排了回顾节奏（日/周/月）？
