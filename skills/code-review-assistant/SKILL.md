# 代码审查助手

> 提交 PR 前自动预审代码变更：发现问题、分类排序、生成修复建议。不是替代人工审查，而是让审查更高效。

## 能力

- **变更范围分析**：自动识别 PR 修改的文件和函数，计算影响范围
- **多维度审查**：安全性（注入/XSS/密钥泄露）→ 逻辑（边界/空值/竞态）→ 性能（N+1/内存/阻塞）→ 风格
- **问题分级**：🔴 阻断 / 🟡 建议 / 🔵 可选 — 按优先级呈现
- **修复建议**：每个问题附带具体修复方案和代码示例
- **PR 描述生成**：自动生成变更摘要和审查关注点

## 使用方式

```
/code-review                   # 审查当前分支相对于 main 的变更
/code-review src/api/           # 审查指定目录
/code-review --audit           # 审查整个代码库
```

## 审查维度

| 维度 | 优先级 | 检查内容 |
|------|--------|---------|
| 安全性 | 最高 | SQL注入、XSS、密钥硬编码、路径遍历、未验证输入 |
| 正确性 | 高 | 空值处理、边界条件、异步错误、类型安全 |
| 可靠性 | 高 | 错误处理完整性、超时设置、重试机制 |
| 性能 | 中 | N+1查询、不必要循环、大对象复制、阻塞操作 |
| 可维护性 | 低 | 命名清晰度、函数长度、重复代码、注释质量 |

## 工作流

1. 运行 `git diff main...HEAD` 获取变更
2. 按上述维度逐文件审查
3. 每个问题输出：文件:行号 → 问题描述 → 严重度 → 修复建议
4. 汇总生成审查报告
5. 可选：直接应用低风险修复

## 适用场景

- 提交 PR 前的自我审查
- 小团队无人力做 formal code review 时的自动化替代
- 新人代码提交前的安全检查
- 重构后验证是否有回归

## 限制

- 不替代人工对业务逻辑的审查
- 安全审查覆盖常见模式但非完整 SAST
- 风格建议遵循项目已有规范，无规范时使用通用最佳实践
